# Как писать карточки

Сценарий лежит в `Core/Sources/MigrantCore/Content/`:

- `game.json` — старт, вступление (`intro`: список строк, пустая строка — новая строфа), акты, концовки;
- `cards/*.json` — карточки, по файлу на акт. Файлы читаются по алфавиту, отсюда префиксы `1_`, `2_`, `3_`.

После любой правки:

```sh
python3 tools/content.py          # проверка ссылок + 2000 случайных прохождений
python3 tools/content.py --play   # сыграть в терминале
```

## Карточка

```json
{
  "id": "fig_cold",
  "kind": "pool",
  "scene": "flat_cold",
  "speaker": "Мама",
  "weight": 3,
  "repeatable": false,
  "requires": { "flags": ["has_flat"], "fromActDay": 40 },
  "text": "Ночью в квартире +14. Отопления нет.",
  "choices": [ ... ]
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | уникальный во всей игре. Префикс акта: `pack_`, `dep_`, `tb_`, `bat_`, `fig_` |
| `text` | да | до ~300 символов |
| `choices` | да | 1–4 кнопки; хотя бы одна без условия |
| `kind` | нет | `pool` (по умолчанию) — может выпасть случайно в своём акте; `event` — только по ссылке |
| `scene` | нет | имя картинки, список — `docs/art.md` |
| `speaker` | нет | кто говорит — подпись над текстом |
| `requires` | нет | когда карточка может появиться |
| `weight` | нет | вес при случайном выборе, по умолчанию 1. `100` — «как только можно, сразу» |
| `repeatable` | нет | может выпасть снова. По умолчанию — один раз за партию |

## Кнопка

```json
{
  "label": "Укрыться бабушкиным пледом",
  "requires": { "flags": ["has_plaid"] },
  "result": "Плед колется и пахнет бабушкиной квартирой.",
  "effects": { "stats": { "nerves": 10, "home": 10 } }
}
```

`result` — текст после нажатия (можно не писать). `requires` — кнопка видна только при условии.

## Эффекты

| Поле | Пример | Смысл |
|---|---|---|
| `stats` | `{ "money": -120, "nerves": 5 }` | шкалы: `money`, `nerves`, `documents`, `home`, `belonging` |
| `set` / `clear` | `["has_nif"]` | поставить / снять флаги |
| `add` | `{ "kg": 3 }` | прибавить к счётчику (килограммы, звонки в AIMA) |
| `next` | `["scales_over", "scales_ok"]` | следующая карточка: **первая, чьё условие выполнено** |
| `schedule` | `[{ "card": "ctt_notice", "inDays": 14 }]` | отложенная карточка через N дней |
| `act` | `"arrival"` | перейти в другой акт |
| `days` | `20` | сколько дней проходит (по умолчанию — `daysPerCard` акта) |
| `ending` | `"demo_end"` | концовка по сюжету |

## Условия

| Поле | Пример | Смысл |
|---|---|---|
| `flags` | `["has_nif", "has_flat"]` | все установлены |
| `notFlags` | `["parcel_declared"]` | ни один не установлен |
| `anyFlags` | `["remote_job", "has_job"]` | хотя бы один |
| `minStats` / `maxStats` | `{ "nerves": 20 }` | шкала не ниже / не выше |
| `minCounters` / `maxCounters` | `{ "kg": 24 }` | счётчик не ниже / не выше (нет счётчика = 0) |
| `fromActDay` | `30` | не раньше 30-го дня **текущего акта** — почти всегда нужен этот |
| `fromDay` | `100` | не раньше 100-го дня **от начала игры** |

## Как выбирается следующая карточка

1. `next` из нажатой кнопки — первая подходящая.
2. Отложенные (`schedule`), чей день наступил, — сначала самые ранние. Если условие карточки к этому моменту не выполнено, она тихо отменяется: задекларированную посылку обратно не отправят.
3. Случайная из колоды текущего акта: `pool`, ещё не показанная (или `repeatable`), с выполненным условием, по весам.
4. Запасная карточка акта (`fallback` в `game.json`).

## Рецепты

**Отложенное последствие.** Кнопка ставит флаг и откладывает карточку; у карточки — условие на флаг.

**Ветвление без кода.** `"next": ["scales_over", "scales_ok"]`: у первой — условие «перевес», вторая — без условий.

**Конец акта.** `pool`-карточка с `weight: 100` и условием «всё главное сделано» (флаги + `fromActDay` или счётчик). Как только условие выполнилось, она выпадает.

**Регулярные события** (аренда, зарплата): карточка-`event` с `repeatable: true`, которая в своём эффекте откладывает саму себя на 30 дней.

**Спасательный круг.** `pool`, `repeatable`, `weight: 30`, условие `maxStats` — выпадает, когда шкала почти на нуле.
